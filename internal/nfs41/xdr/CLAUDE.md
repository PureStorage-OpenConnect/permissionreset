# internal/nfs41/xdr

Generated NFSv4.1 XDR bindings. Nothing here is hand-written by Everpure
except `types.go`. Do not hand-edit `xdr_generated.go`.

## Files

- **`nfs4.x`** — NFSv4 XDR description (RFC 3530 base + RFC 5661 additions).
  Four Everpure modifications, all marked inline: added EXCHANGE_ID block,
  removed callback section, completed nfsstat4 enum to RFC 5662.
- **`rpc.x`** — ONC RPC message format (RFC 5531). One modification: removed
  duplicate `RPCSEC_GSS`, added `AUTH_TLS = 7` (RFC 9289, unused today).
- **`xdr_generated.go`** — 16.5K lines generated by goxdr v0.1.3 (Apache-2.0
  elected). Lines 15721–16500 are goxdr runtime boilerplate bundled via `-B`.
  Must be byte-stable: `make regen-xdr` must leave working tree clean.
- **`types.go`** — hand-written upstream (Cyberax/go-nfs-client, Apache-2.0).
  Supplies `uint32_t`/`uint64_t`/`int64_t` type aliases that `.x` uses but
  goxdr does not provide as builtins. NOT reproduced by `make regen-xdr`.
- **`PROVENANCE.md`** — full provenance, license analysis, regeneration
  instructions, RFC verification record.

## Regenerating

```bash
make regen-xdr
```

Must leave working tree clean. Gates after regen: builds, zero external deps,
go.mod/go.sum untouched.

## Key types used by parent package

- `Nfs_argop4` / `Nfs_resop4` — COMPOUND operation args/results (union on opnum)
- `Nfsstat4` — status enum (0 = OK through 10087)
- `OP_*` constants — operation numbers
- `FATTR4_*` constants — attribute bit numbers
- `NFS4ERR_*` — status codes
- `COMPOUND4args` / `COMPOUND4res` — top-level COMPOUND request/reply
- `SEQUENCE4args` / `CREATE_SESSION4args` / `EXCHANGE_ID4args` — session ops

## Do not

- Hand-edit `xdr_generated.go` (breaks byte-stability guarantee)
- Add `BIND_CONN_TO_SESSION` to `nfs4.x` (client must never send it)
- Fork goxdr (maintenance burden for a problem confined to four reply types)
- Trust upstream's committed `.go` — not reproducible from upstream's `.x`
